# Motion Garden as an open agentic website

This folder makes Motion Garden an open agentic website, as defined in the
[Worldwide Agentic Web MVP spec](https://github.com/cognizant-ai-labs/agentic-web/blob/main/docs/worldwide_agentic_web_mvp_spec.md).
It was built with the agentic-web repository's `agentify-website` skill, adapted from a
static site to this Next.js app.

- **Network URL:** `https://motion-garden.netlify.app/agent/motion_garden`
- **Manifest:** `https://motion-garden.netlify.app/agent/agent-manifest.json`
- **Where visitors use it:** the **Ask the Garden** button on every catalog page
  (`components/agent/AgentPanel.tsx`, mounted in `app/(shell)/layout.tsx`).

## What it does

The network has two agents:

| Agent | Job |
| --- | --- |
| `garden_guide` (front) | Finds components, explains their controls, opens them and tunes the live preview. |
| `integration_helper` | Reads one component's full integration brief and returns the install command, files, code and the steps for the visitor's stack. It exists so the long brief stays out of the guide's context on every other turn. |

They act through seven site actions. The model sees each as `website_<name>`:

| Action | Effect | What it wraps |
| --- | --- | --- |
| `get_bench_state` | read | The open component and each control's live value, default and range (`lib/agent/bench-bridge.ts`) |
| `search_components` | read | `GET /api/agent/search` (`lib/agent/search.ts`) |
| `describe_component` | read | `GET /api/agent/component/[slug]` (`lib/agent/describe.ts`) |
| `get_component_code` | read | `GET /api/agent/component/[slug]?brief=1`, the same brief as the page's **Copy for Agent** button (`lib/registry/prompt.ts`) |
| `open_component` | write | Client-side navigation to `/components/<slug>`, with optional starting values |
| `set_controls` | write | The bench's own nuqs setter (`useTunedProps().setMany`), after checking every value against the component's `PropSchema` |
| `reset_controls` | write | The bench's own reset |

Every write can be undone on the page, so nothing asks for confirmation. A refused
change returns `{ok: false, reason, field}` and changes nothing. The assistant declines
anything the site cannot do, such as creating components or editing the visitor's
project.

## What other sites get

A site that lists the network URL in an agent's `tools`, and `https://motion-garden.netlify.app`
in its `allowed_peers`, can ask Motion Garden after its visitor agrees on a consent card.
The network then runs in that visitor's browser, on their key. Through
`bridge/bridge-actions.js` it shares three reads with every origin (`"*"`), because they
return only public, MIT-licensed catalog facts: `search_components`,
`describe_component` and `get_component_code`. The bench actions stay on Motion Garden's
own page.

## Files

| Path | What it is |
| --- | --- |
| `motion_garden.hocon` | Source of truth for the network |
| `motion_garden.network.json` | Generated from the HOCON. Do not edit |
| `agent-manifest.json` | Network, default router (hosted Otari), peer policy, actions |
| `links.json` | Peer link map (empty: the network calls no partner) |
| `site.js` | Boots the runtime in the drawer |
| `site-actions.js`, `garden-data.js` | The site actions |
| `assistant.css` | Runtime styles mapped onto the bench's `--sg-*` tokens |
| `bridge/bridge-actions.js` | The reads shared with other sites |
| `bridge/action-bridge.html`, `bridge/agent-manifest.json`, `agent-mcp.json`, `.well-known/` | Generated by the build. Do not edit |
| `runtime/` | The patched nsdeploy browser runtime (Apache 2.0), copied unchanged from the skill |
| `package.json` | Marks this folder's `.js` files as ES modules for Node |

## Privacy

The assistant sends the visitor's messages, and the page data it reads, to the AI
provider the visitor picks in **AI model settings**. The key stays in this origin's
browser storage. It is sent only to that provider, never to Motion Garden or to another
site. Everything in the network file, including the instructions, is public by design.

## Build and check

From the repo root, with `SKILL_DIR` set to `skills/agentify-website` in a checkout of
[cognizant-ai-labs/agentic-web](https://github.com/cognizant-ai-labs/agentic-web):

```bash
node SKILL_DIR/scripts/build_network.mjs public/agent/motion_garden.hocon --manifest public/agent/agent-manifest.json
node SKILL_DIR/scripts/build_network.mjs public/agent/motion_garden.hocon --manifest public/agent/agent-manifest.json --check
node SKILL_DIR/scripts/check_partner.mjs http://localhost:3000/agent/motion_garden
bun run check:agent
```

The skill's Node DOM tests are not used: they drive a static page script, and this
bench is a React app. `bun run check:agent` checks the action logic against the real
registry instead, and the actions were checked in a browser through the runtime's own
action registry.

## Hosting

The public files need `Access-Control-Allow-Origin: *`, and `runtime/sandbox-worker.js`
needs its own Content-Security-Policy. Both are set twice: in `next.config.ts` and in
`netlify.toml`, because the CDN serves `public/` without running Next. `bridge/` must not
send `X-Frame-Options` or `frame-ancestors`, since callers load it in a hidden frame.

## Limits

- The runtime is a patched copy of nsdeploy's, kept unchanged here.
- `write` actions run without a dialog. The spec asks to show writes first; every write
  here only changes the bench, which the visitor can undo.
- Every agent can see every `website_*` tool. Instructions scope them.
- The LLM provider must allow browser (CORS) requests. Hosted Otari, OpenRouter, OpenAI
  and Anthropic do.
- Briefs over 30,000 characters (most landing-page templates) are not sent through
  the chat. The assistant points to the page's **Copy for Agent** button instead.
